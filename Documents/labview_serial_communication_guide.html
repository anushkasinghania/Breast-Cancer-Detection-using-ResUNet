1. System Overview & Architecture

The program uses a Producer-Consumer design pattern — the standard LabVIEW architecture for decoupling the user interface from deterministic hardware I/O. Two parallel loops run simultaneously:

Producer Loop (GUI / Event-Driven)

Runs in the normal LabVIEW priority. It waits for front-panel events (button clicks, knob changes, command selection) and enqueues command data into a LabVIEW Queue. It never touches the serial port directly.

Consumer Loop (Timed Loop — 5 ms period)

Runs in a Timed Loop (or on an RT target for hard real-time). Every 5 ms it dequeues the latest command, builds the serial frame (with STX EB 90, payload, checksum), writes it via VISA Write, and optionally reads a response via VISA Read.

Why Producer-Consumer? — The GUI runs at human speed (event-driven, irregular). The serial transmit must run at a strict 5 ms cycle. A queue decouples the two: the GUI pushes commands whenever the user acts; the timed loop pulls commands at a fixed rate and always sends the latest one, even if the user hasn't clicked anything new.

Baud-rate math: 115200 bps ÷ 10 bits/byte (8N1) = 11,520 bytes/sec. In 5 ms you can transmit ~57 bytes. A typical command frame is 10–20 bytes, so 115200 bps provides comfortable margin. If your frame is larger, consider 230400 or 460800 bps.

4. All Block-Diagram Components

Here is every LabVIEW VI, function, and node you need, grouped by purpose:

A. Serial Port Configuration

VI VISA Configure Serial Port.vi — Sets COM port, baud rate (115200), data bits (8), stop bits (1), parity (none), flow control (none). Found in Instrument I/O → Serial palette.

VI VISA resource name (control) — Front-panel dropdown listing available COM ports (e.g., COM3, ASRL3::INSTR).

B. Serial Read & Write

VI VISA Write.vi — Sends the assembled string (binary frame) out the serial port.

VI VISA Read.vi — Reads response bytes from the control box. Wire byte count to expected response length.

VI VISA Close.vi — Closes the serial session on program exit.

FN VISA Bytes at Serial Port (property node) — Check how many bytes are available before reading.

C. String & Hex Operations

FN Concatenate Strings — Joins STX + CMD ID + LEN + DATA + CHKSUM into one binary string.

FN String to Byte Array — Converts a LabVIEW string to U8 array for checksum calculation.

FN Byte Array to String — Converts U8 array back to string for VISA Write.

FN Hexadecimal String to Number — Parses hex input from the user (e.g., typing "EB90" in a text box).

FN Number to Hexadecimal String — Displays bytes as hex on the front panel for debugging.

FN Type Cast — Casts numeric values (DBL, I16) to their raw byte representation for the DATA payload.

D. Queue Operations

FN Obtain Queue — Creates a named queue (data type = cluster of command info). Place before both loops.

FN Enqueue Element — Producer loop pushes a new command into the queue.

FN Dequeue Element — Consumer loop pulls the next command. Set timeout = 0 ms (non-blocking) so the timed loop never stalls.

FN Flush Queue — Optionally clear stale commands when switching modes.

FN Release Queue — Destroys the queue on program exit (after both loops stop).

E. Loop Structures

LOOP Event Structure (inside a While Loop) — The Producer loop. Waits for front-panel events (Value Change on buttons/controls) with zero CPU usage.

LOOP Timed Loop — The Consumer loop. Configured for 5 ms period (dt = 5,000 µs). Uses the OS or RT clock for deterministic timing.

LOOP While Loop — Wraps the Event Structure in the Producer side; also used if you need an inner polling loop.

F. Timing & RT

HW Timed Loop Input Node — Configure: Period = 5 ms, Priority = highest, Processor = 0 (for RT target).

FN Tick Count (ms) — For jitter measurement / debugging the loop timing.

FN Wait Until Next ms Multiple — Alternative to Timed Loop for non-RT targets (less deterministic but simpler).

G. Error Handling

FN Error Cluster — Wire the error in / error out chain through every VISA node.

VI Simple Error Handler.vi — Place after VISA Close to display errors on exit.

7. Step-by-Step Wiring Instructions

Follow these steps in order on the LabVIEW block diagram. Each step tells you exactly what to place and what to wire to what.

Place VISA Configure Serial Port.vi
Go to Functions → Instrument I/O → Serial → VISA Configure Serial Port. Drop it on the block diagram. Create a control on its VISA resource name input (right-click → Create Control). This creates the COM port dropdown on the front panel. Wire constants to: Baud Rate = 115200, Data Bits = 8, Stop Bits = 1.0, Parity = 0 (None), Flow Control = 0 (None).
Place Obtain Queue
Go to Functions → Data Communication → Queue Operations → Obtain Queue. Drop it to the right of the VISA Configure node. Right-click the element data type input and create a constant — make it a Cluster containing: CMD_ID (U8), Amplitude (DBL), Frequency (DBL), StepValue (I32), Offset (I32). This cluster is your "command message" that travels through the queue.
Place the Producer While Loop
Go to Functions → Structures → While Loop. Draw a large rectangle on the left side of the diagram (below the init nodes). Right-click inside it and select Event Structure — this goes inside the While Loop. Wire the queue reference output from Obtain Queue into the While Loop (it passes through the tunnel automatically).
Configure Event Structure Cases
Right-click the Event Structure border → Add Event Case. Create one case for each front-panel button:
• "Step" Value Change — Inside: Bundle the command cluster with CMD_ID = 0x01 + the Step Value control.
• "Sine" Value Change — Inside: Bundle with CMD_ID = 0x02 + Amplitude + Frequency.
• "Profile" Value Change — Inside: Bundle with CMD_ID = 0x03 + profile parameters.
• "Functional Test" Value Change — Inside: Bundle with CMD_ID = 0x10.
• "Stop" Value Change — Inside: Set the loop condition terminal to TRUE (stops both loops). Also enqueue a "stop" command (CMD_ID = 0xFF).
Wire Enqueue Element inside each Event Case
In each event case (except Stop), place an Enqueue Element function. Wire the queue reference (from the tunnel) to its queue input. Wire the bundled command cluster to its element input. This pushes the command into the queue whenever the user clicks a button.
Place the Consumer Timed Loop
Go to Functions → Structures → Timed Structures → Timed Loop. Draw it on the right side. Click the input node (left side of the Timed Loop) and configure: Period = 5000 µs (= 5 ms), Offset = 0, Priority = Highest. Pass the VISA session and queue reference into this loop through tunnels.
Dequeue Element inside the Timed Loop
Place Dequeue Element inside the Timed Loop. Wire the queue reference to it. Set timeout = 0 ms (non-blocking). Wire the timed out? output to a Case Structure: if not timed out, use the new command; if timed out, use a Shift Register on the Timed Loop to reuse the last command (so it keeps sending the same command every 5 ms until the user changes it).
Build the Serial Frame (String Concatenation)
Inside the Timed Loop, after the dequeue/case structure:
a) Place a String Constant with the hex value \EB\90 — this is your STX. (In LabVIEW, type \EB\90 in the string constant with "Hex Display" mode, or use backslash codes.)
b) Use Type Cast to convert CMD_ID (U8) to a 1-byte string.
c) Use Type Cast to convert each numeric parameter to its byte-string representation.
d) Calculate LEN = String Length of the data portion. Type Cast LEN (U8) to a 1-byte string.
e) Place Concatenate Strings (Functions → String → Concatenate Strings). Expand it to have 4+ inputs. Wire in order: STX string → CMD_ID string → LEN string → DATA string.
f) For Checksum: Use String to Byte Array on the portion from CMD_ID through DATA. Use a For Loop with XOR to compute the checksum byte. Convert back to a 1-byte string. Concatenate it at the end.
Wire VISA Write
Place VISA Write (Functions → Instrument I/O → Serial). Wire the VISA session (from the tunnel) to its VISA resource name input. Wire the concatenated frame string to its write buffer input. Wire error in from the previous node.
Wire VISA Read (optional — for response)
Place VISA Read after VISA Write. Wire the VISA session. Set byte count to your expected response length (e.g., 10 bytes). Wire the read buffer output to a front-panel String Indicator (set to Hex Display) so you can see the response. If the control box doesn't respond, you can skip VISA Read or use Bytes at Serial Port property to check first.
Add Timing Monitor
Place Tick Count (ms) at the start and end of the Timed Loop body. Subtract them to get actual loop execution time. Wire to a front-panel Numeric Indicator labeled "Loop Time (ms)". This lets you verify the 5 ms cycle is being met.
Wire the Stop Condition
Create a Local Variable of the Stop button. Read it inside the Timed Loop and wire to its stop terminal. Both loops must stop together: the Producer's While Loop stops from the Event Structure; the Consumer's Timed Loop stops from the local variable.
Cleanup — After Both Loops
Outside and below both loops, place (in this order, wired sequentially via error chain):
a) VISA Close — wire the VISA session from the Consumer loop's output tunnel.
b) Release Queue — wire the queue reference.
c) Simple Error Handler.vi — wire error out. This pops up a dialog if any VISA error occurred.

8. Command Types

Step Command (CMD ID: 0x01)

Sends a fixed setpoint value to the control box. The output jumps from 0 to the target value instantly. Used for step-response testing.

Frame: EB 90 | 01 | 04 | [StepValue as I32, 4 bytes] | [XOR checksum]
Example: EB 90 01 04 00 00 03 E8 EC   → Step to 1000 (0x03E8)

GUI controls: Step Value numeric input, Start/Stop toggle.

Sine Command (CMD ID: 0x02)

Commands the control box to follow a sinusoidal waveform. The LabVIEW program sends amplitude and frequency; the control box generates the sine internally, or LabVIEW computes and sends discrete sine samples every 5 ms.

Frame: EB 90 | 02 | 0C | [Amplitude DBL 8 bytes] [Freq U16 2 bytes] [Offset I16 2 bytes] | [XOR]
Example: EB 90 02 0C 40 8F 40 00 00 00 00 00 00 0A 00 00 [chk]
         → Amplitude=1000.0, Frequency=10 Hz, Offset=0

GUI controls: Amplitude knob/numeric, Frequency slider, Offset numeric.

Profile Command (CMD ID: 0x03)

Sends a user-defined motion profile: a series of time-value pairs that the control box follows as a trajectory. This can be a ramp, triangle wave, trapezoidal profile, or arbitrary shape.

Frame: EB 90 | 03 | [2+8*N] | [N points U16] [Time1 U32][Val1 I32] [Time2 U32][Val2 I32] ... | [XOR]
Example: 3-point profile (ramp up, hold, ramp down)

GUI controls: Profile table (array of time-value rows), Load from File button.

Functional Test Command (CMD ID: 0x10)

Triggers a built-in self-test routine in the control box. The box runs through predefined test sequences and reports pass/fail status. Used during commissioning and diagnostics.

Frame: EB 90 | 10 | 01 | [Test ID U8] | [XOR]
Example: EB 90 10 01 01 00 → Run test #1
Response expected: EB 90 90 02 [TestID] [Result: 00=pass, 01=fail] [XOR]

GUI controls: Test ID selector, Run Test button, Pass/Fail LED indicator.

Reset Command (CMD ID: 0xFF)

Commands both control boxes to return to their default/safe state. Zeroes all outputs. Sent when the user presses STOP or RESET.

Frame: EB 90 | FF | 00 | [XOR = FF]

9. Timed Loop & 5 ms Cyclic Guarantee

The Timed Loop is critical — it's what makes this program send commands at exactly 5 ms intervals instead of "approximately" 5 ms.

Timed Loop vs. While Loop + Wait

FeatureWhile + Wait (ms)Timed Loop
Period accuracy±1–10 ms (OS-dependent)±0.1 ms (hardware clock)
Drift compensationNone — accumulatesBuilt-in — self-corrects
Priority controlNoneYes — can run at highest priority
Jitter reportingManualBuilt-in (dt actual output)
RT target supportNot deterministicHard real-time on RT

Timed Loop Configuration

Period: 5,000 µs (= 5 ms = 200 Hz cycle rate)

Offset: 0 µs (no phase offset — only matters with multiple Timed Loops)

Priority: Set to highest (ensures the serial TX runs even if other loops are busy)

Source Type: "1 kHz Clock" on Windows, "RT Hardware Clock" on PXIe RT target

RT Target Consideration: On a standard Windows PC, the Timed Loop achieves ~±0.5 ms jitter. For guaranteed ±0.05 ms jitter, deploy the Consumer loop as an RT VI on the PXIe-1082's RT controller. The Producer (GUI) stays on the Windows host and communicates via a network-published shared variable or RT FIFO instead of a local queue.

10. Queue Logic Explained

Why a Queue?

The fundamental problem: the user clicks buttons at random times (0–∞ ms apart), but the serial port must send a command every 5 ms without fail. A queue solves this by acting as a thread-safe mailbox between the two loops.

Data Flow

1. User clicks "Step" → Producer bundles {CMD_ID=0x01, StepValue=1000} into a cluster and calls Enqueue Element.

2. Consumer's Dequeue Element (timeout=0) → If a new command is in the queue, it uses it. If the queue is empty (timed out), the shift register feeds back the previous command — so the consumer keeps sending the last known command every 5 ms.

3. User clicks "Sine" → A new cluster overwrites the queue. Next consumer iteration picks it up.

4. User clicks "Stop" → A reset command (0xFF) is enqueued, and the stop boolean is set.

Queue Size

Set the queue max size to 1 (or use Lossy Enqueue) so only the latest command matters. If the user clicks rapidly, you don't want 50 commands queued up — you want the most recent one immediately.
