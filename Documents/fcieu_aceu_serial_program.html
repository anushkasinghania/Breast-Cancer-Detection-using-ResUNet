1. System Architecture — Who Talks to Whom

Physical Setup

FCIEU Flight Control Interface Electronics Unit — this is what your LabVIEW program simulates. It sends fin deflection commands and test commands to the ACEU.

ACEU Actuator Control Electronics Unit — the real hardware box. It receives commands, drives the 4 fin actuators, and sends back status/response data.

Your LabVIEW program acts as the FCIEU. It sends. The ACEU hardware responds.

*Total Frame = 2 (STX) + 1 (MSG ID) + 1 (MSG LEN) + MSG LEN (DATA) + 1 (Checksum) = MSG LEN + 5

3. Exact Frame Byte Layouts (LSB-First)

LSB-First means: When a multi-byte number is placed into the DATA field, the Least Significant Byte goes first (lowest address). Example: deflection value 0x0186A0 (100000 in decimal) is sent as A0 86 01, NOT 01 86 A0. LabVIEW's default is big-endian, so you must use Swap Bytes or Reverse String before placing data in the frame.

3a. Cyclic Command Frame (FCIEU → ACEU)

EB90 90 0C F1LF1MF1H F2LF2MF2H F3LF3MF3H F4LF4MF4H XOR 
Byte 0-1: EB 90         (STX — fixed)
Byte 2:   90             (MSG ID — cyclic command)
Byte 3:   0C             (MSG LEN = 12 decimal)
Byte 4-6: Fin1 deflection (3 bytes, LSB first)
Byte 7-9: Fin2 deflection (3 bytes, LSB first)
Byte 10-12: Fin3 deflection (3 bytes, LSB first)
Byte 13-15: Fin4 deflection (3 bytes, LSB first)
Byte 16:  XOR checksum (XOR of bytes 2 through 15)

Example: All 4 fins at 1000 (0x0003E8)
LSB-first: E8 03 00
Frame: EB 90 90 0C E8 03 00 E8 03 00 E8 03 00 E8 03 00 [XOR]

3b. Cyclic Response Frame (ACEU → FCIEU)

EB90 9A 4A 74 bytes of status/telemetry data XOR 
Total: 79 bytes.  VISA Read byte count = 79
MSG LEN = 0x4A = 74 decimal

3c. Write Config Frame

SEND:     EB 90 B1 36 [54 config bytes, LSB-first] [XOR]    → 59 bytes total
RECEIVE:  EB 90 B0 01 [00=OK / 01=FAIL] [XOR]                → 6 bytes total

3d. Read Config Frame

SEND:     EB 90 B0 00 [XOR]                                  → 5 bytes total
RECEIVE:  EB 90 B0 36 [54 config bytes] [XOR]                 → 59 bytes total

3e. Functional Test Frame

SEND:     EB 90 93 0E [14 bytes: test_type(1) + params(13)] [XOR]  → 19 bytes total
          test_type: 0x00 = Cyclic Test, 0x01 = Step Test
RECEIVE:  EB 90 63 21 [33 bytes of results] [XOR]                   → 38 bytes total

4. Fin Deflection Data — 4 Fins × 3 Bytes

Each fin = 3 bytes = 24-bit signed integer

24 bits gives a range of −8,388,608 to +8,388,607. This typically represents a fixed-point deflection angle (e.g., angle × 1000 or angle × 10000 for sub-degree precision).

FinByte Position in DATALSB-First OrderExample: +15.5°
Fin 1Byte 4, 5, 6Low, Mid, HighIf 15500 = 0x003C8C → sent as 8C 3C 00
Fin 2Byte 7, 8, 9Low, Mid, High
Fin 3Byte 10, 11, 12Low, Mid, High
Fin 4Byte 13, 14, 15Low, Mid, High

LabVIEW conversion: I32 → 3 bytes LSB-first

1. Take the I32 value from the front-panel control (e.g., 15500)
2. Type Cast I32 → 4-byte string (LabVIEW gives Big-Endian: 00 00 3C 8C)
3. Reverse String → 8C 3C 00 00 (now LSB-first)
4. String Subset (offset=0, length=3) → 8C 3C 00 (trim to 3 bytes)
5. Repeat for all 4 fins, concatenate → 12 bytes total

7. Shift Register Logic — Why & How

The Problem

The Timed Loop fires every 5 ms. The user might click a fin value once, then not touch anything for 10 seconds. During those 10 seconds the queue is empty — but the ACEU still expects a cyclic command every 5 ms. Without a shift register, the consumer would have nothing to send.

The Solution: Shift Register

A Shift Register is a pair of terminals on the left and right walls of the Timed Loop. Whatever you wire to the right terminal at the end of one iteration becomes available at the left terminal at the start of the next iteration.

How it works every 5 ms:

  ┌─ Dequeue (timeout=0) ─────────────────────────────────┐
  │                                                        │
  │  Queue has new command?                                │
  │    YES → use it → also write it to Shift Register (R)  │
  │    NO  → read Shift Register (L) → use last command    │
  │                                                        │
  │  Build frame from whichever command we're using        │
  │  VISA Write → VISA Read                                │
  └────────────────────────────────────────────────────────┘

LabVIEW Wiring

Right-click the left or right border of the Timed Loop → Add Shift Register. Wire the output of the Case Structure (the resolved command cluster) to the right terminal. Wire the left terminal into the "TRUE" case of the "Timed out?" Case Structure. Initialize the shift register by wiring a default command cluster (all zeros, Mode=0) to the left terminal from outside the loop.

8. Step-by-Step Wiring — Every Connection

Phase A: Initialization (Outside Loops)

Place VISA Configure Serial Port.vi — Create control on VISA resource name. Constants: baud = 115200, data bits = 8, parity = 0, stop bits = 1.0, flow = 0.
Place Obtain Queue — Right-click "element data type" → Create Constant → make it a Cluster:
• Mode (U8)
• Fin1 (I32), Fin2 (I32), Fin3 (I32), Fin4 (I32)
• TestType (U8)
• ConfigData (Array of U8, 54 elements)
Wire VISA error out → Obtain Queue error in.
Create STX String Constant — String constant in \Hex Display mode: type EB90. This wire will pass into the Consumer loop.

Phase B: Producer Loop (Left Side)

Draw a While Loop. Inside it, place an Event Structure. Pass the queue reference into the loop through a tunnel.
Event Case: "Cyclic / Fin Value Change" — Add event for Value Change of any of the 4 fin numeric controls. Inside:
a) Place Bundle By Name — create the FCIEU_Command cluster.
b) Set Mode = 0.
c) Wire the 4 fin I32 controls into Fin1–Fin4 fields.
d) Place Enqueue Element. Wire queue ref and the bundled cluster.
Event Case: "Write Config" — Same pattern: Mode = 1, wire a 54-element U8 array from a front-panel array control into ConfigData field. Enqueue.
Event Case: "Read Config" — Mode = 2. No data fields needed (all zeros). Enqueue.
Event Case: "Functional Test" — Mode = 3. Wire TestType (0 or 1 from a front-panel radio/enum control). Enqueue.
Event Case: "STOP" — Mode = 0xFF. Enqueue. Wire TRUE to the While Loop's stop condition terminal.

Phase C: Consumer Timed Loop (Right Side)

Draw a Timed Loop. Click the left-wall input node. Set: Period = 5000 µs, Priority = Highest. Pass VISA session, queue ref, and STX string through tunnels.
Add Shift Register — Right-click the Timed Loop border → Add Shift Register. Initialize the left terminal with a default cluster (Mode=0, all fins=0). This is the "last command" memory.
Place Dequeue Element inside the Timed Loop. Wire queue ref. Wire timeout = 0 (constant). This makes it non-blocking.
Place Case Structure for "timed out?" — Wire the timed out? boolean output of Dequeue Element to a Case Structure.
• FALSE case (new command arrived): wire the dequeued cluster out.
• TRUE case (queue empty): wire the Shift Register left terminal (last command) out.
Both cases output the same cluster type through the output tunnel.
Wire the resolved command to Shift Register right terminal — so it becomes "last command" for next iteration.
Unbundle Mode — Place Unbundle By Name on the resolved command cluster. Read the Mode field. Wire it to a Case Structure with 4 cases (0, 1, 2, 3).
Case 0 — Cyclic Frame Builder:
a) Unbundle Fin1, Fin2, Fin3, Fin4 (each I32).
b) For each fin, do the LSB-first conversion:
   • Type Cast I32 → 4-byte string (big-endian).
   • Reverse String → now LSB-first.
   • String Subset (offset=0, length=3) → trim to 3 bytes.
c) Concatenate Strings (expand to 4 inputs): Fin1_3bytes + Fin2_3bytes + Fin3_3bytes + Fin4_3bytes → 12-byte DATA.
d) Create MSG ID constant: string \90 (hex display).
e) Create MSG LEN constant: string \0C (hex, = 12).
f) Concatenate Strings: MSG_ID + MSG_LEN + DATA_12bytes → "payload without STX" (14 bytes).
g) XOR Checksum: String to Byte Array → For Loop with XOR shift register → 1-byte result → Type Cast U8 to string.
h) Final Concatenate Strings: STX + payload_14bytes + checksum_1byte → 17-byte frame.
i) Wire 79 (constant) to the "read_byte_count" output tunnel.
Case 1 — Write Config Frame Builder:
a) Unbundle ConfigData (U8 array, 54 elements).
b) Byte Array to String → 54-byte string.
c) MSG ID = \B1, MSG LEN = \36 (54 decimal = 0x36).
d) Concatenate: MSG_ID + MSG_LEN + 54 data bytes → payload (56 bytes).
e) XOR checksum → Final: STX + payload + checksum → 59 bytes.
f) Read count = 6.
Case 2 — Read Config Frame Builder:
a) MSG ID = \B0, MSG LEN = \00.
b) No data bytes.
c) XOR checksum of just MSG_ID + MSG_LEN = 0xB0 XOR 0x00 = 0xB0.
d) Final: STX + \B0\00\B0 → 5 bytes total.
e) Read count = 59.
Case 3 — Functional Test Frame Builder:
a) Unbundle TestType (U8). Type Cast to 1-byte string.
b) Build 13 parameter bytes (from front-panel controls or constants).
c) MSG ID = \93, MSG LEN = \0E (14 decimal).
d) Concatenate: MSG_ID + MSG_LEN + TestType_1byte + params_13bytes → 16-byte payload.
e) XOR checksum → Final: STX + payload + checksum → 19 bytes.
f) Read count = 38.
VISA Write — Wire the frame string output from the Case Structure → VISA Write's write buffer. Wire VISA session. Also create an Indicator (Hex Display) to show the TX frame.
VISA Read — Wire VISA session from VISA Write's output. Wire read_byte_count from the Case Structure to VISA Read's byte count. Create an Indicator (Hex Display) for the response.
Parse Response — After VISA Read:
a) String Subset (offset=0, length=2) — verify = EB 90.
b) String Subset (offset=2, length=1) — extract MSG ID.
c) Compare MSG ID to expected. Route through Case Structure to decode response-specific data.
d) For cyclic response (0x9A): extract 74 bytes of telemetry and wire to indicators.
Stop condition — Read a local variable of the STOP button. Wire to the Timed Loop's stop terminal.

Phase D: Cleanup (After Both Loops)

VISA Close → Release Queue → Simple Error Handler, all wired via the error chain. VISA session comes from the Consumer loop's output tunnel.

10. Response Parsing — ACEU Reply Decode

After VISA Read, parse the response string:

1. String Subset(offset=0, len=2) → compare to "EB90" (hex) → if no match, flag error
2. String Subset(offset=2, len=1) → MSG ID byte:
     0x9A → Cyclic response (74 data bytes follow)
     0xB0 → Config response (either 1 byte ACK or 54 config bytes — check LEN)
     0x63 → Functional test result (33 data bytes)
3. String Subset(offset=3, len=1) → MSG LEN → tells you how many data bytes
4. String Subset(offset=4, len=MSG_LEN) → DATA payload
5. Last byte → received checksum → compare to XOR of bytes 2 through (3+MSG_LEN)

For cyclic response (0x9A, 74 bytes):
  - Bytes 0-2: Actual Fin1 position (3 bytes, LSB first → Reverse → pad to 4 → Type Cast to I32)
  - Bytes 3-5: Actual Fin2 position
  - Bytes 6-8: Actual Fin3 position
  - Bytes 9-11: Actual Fin4 position
  - Bytes 12-73: Other telemetry (status, temperature, voltage, etc.)

LSB-First → I32 Conversion (for received 3-byte values)

1. String Subset — extract 3 bytes
2. Concatenate: 3 bytes + "\00" (pad to 4 bytes)   ← if positive values only
   OR: sign-extend the MSB if negative values possible
3. Reverse String → now Big-Endian (LabVIEW native)
4. Type Cast → I32

11. Full Pseudocode — What Runs Each 5 ms

── INIT (once) ──
session = VISA_Configure("COM3", 115200, 8, 1, None, None)
queue   = Obtain_Queue(FCIEU_Command)
STX     = "\xEB\x90"
last_cmd = {Mode=0, Fin1=0, Fin2=0, Fin3=0, Fin4=0, TestType=0, Config=[]}

── PRODUCER (event-driven, runs in While Loop) ──
LOOP:
  wait for front-panel event:
    Fin value changed → Enqueue {Mode=0, Fin1, Fin2, Fin3, Fin4}
    Write Config btn  → Enqueue {Mode=1, ConfigData=array[54]}
    Read Config btn   → Enqueue {Mode=2}
    Func Test btn     → Enqueue {Mode=3, TestType=0|1}
    STOP btn          → Enqueue {Mode=0xFF}; exit loop

── CONSUMER (Timed Loop, every 5 ms) ──
TIMED LOOP (period = 5000 µs):
  cmd = Dequeue(timeout=0)
  if timed_out:
    cmd = last_cmd                     ← SHIFT REGISTER left terminal
  last_cmd = cmd                       ← SHIFT REGISTER right terminal

  SWITCH cmd.Mode:
    CASE 0 (Cyclic):
      fin_bytes = ""
      FOR each fin in [Fin1, Fin2, Fin3, Fin4]:
        raw = TypeCast_I32_to_String(fin)      → 4 bytes big-endian
        rev = Reverse(raw)                      → 4 bytes LSB-first
        fin_bytes += Subset(rev, 0, 3)          → 3 bytes LSB-first
      msg_id  = "\x90"
      msg_len = "\x0C"
      read_count = 79

    CASE 1 (Write Config):
      data = ByteArrayToString(cmd.ConfigData)  → 54 bytes
      msg_id  = "\xB1"
      msg_len = "\x36"
      read_count = 6

    CASE 2 (Read Config):
      data = ""                                  → 0 bytes
      msg_id  = "\xB0"
      msg_len = "\x00"
      read_count = 59

    CASE 3 (Functional Test):
      data = TypeCast_U8(cmd.TestType) + param_bytes(13)
      msg_id  = "\x93"
      msg_len = "\x0E"
      read_count = 38

  payload = msg_id + msg_len + data              ← everything after STX
  checksum = XOR_all_bytes(payload)              ← single byte
  frame = STX + payload + TypeCast_U8(checksum)

  VISA_Write(session, frame)                     ← send to ACEU
  response = VISA_Read(session, read_count)      ← read ACEU reply

  verify STX, MSG ID, checksum in response
  extract & display data on front panel

── CLEANUP (once) ──
VISA_Close(session)
Release_Queue(queue)
SimpleErrorHandler(error)
Summary of every keyword used: serial communication (whole program), VISA port (VISA Configure/Write/Read/Close), COM port (VISA Resource control), baud rate (115200), string concatenation (Concatenate Strings to build frame), STX EB90 (2-byte sync header), hex base addressing (all MSG IDs and data in hex), communication protocol (frame structure with ID/LEN/DATA/CHK), Timed Loop (5 ms consumer), cyclic (repeating TX every 5 ms), queue logic (Producer-Consumer with Obtain/Enqueue/Dequeue/Release), transmit queue (Consumer dequeues and transmits), RT (Timed Loop supports RT target), shift register (last command memory), LSB first (Reverse String + Subset), step/sine/profile → fin deflection commands, functional test (0x93 with cyclic/step test types), reset (Mode=0xFF stop command), loop (While + Timed), read (VISA Read response from ACEU).
